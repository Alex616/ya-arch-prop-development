# Чек-лист для подготовки к аудиту безопасности PropDevelopment

## Обоснование выбора разделов

Данный чек-лист адаптирован под конкретные проблемы компании PropDevelopment и сфокусирован на решении критических задач безопасности. При отборе разделов использовались следующие критерии:

### Критерии отбора

1. **Прямая связь с существующими проблемами компании**
   - Изоляция данных партнёров и клиентов
   - Утечки данных между клиентами (отображение чужих ФИО в личных кабинетах)
   - Несколько точек регистрации без координации

2. **Соответствие требованиям законодательства РФ**
   - Обработка персональных данных клиентов и собственников
   - Обработка финансовых данных (ЖКХ, сделки)
   - Интеграция с госорганами

3. **Разблокирование бизнес-развития**
   - Создание основы для ML/AI сервисов
   - Обеспечение Data Governance

4. **Реалистичность выполнения**
   - Учёт ограничений: один специалист по ИБ
   - Фокус на критичных проблемах безопасности
   - Исключение задач, не блокирующих прохождение аудита

### Обоснование включённых разделов

#### I. Управление доступом

**Почему включён:**

- Прямая связь с проблемой изоляции данных партнёров (партнер может видеть данные других партнёров)
- Проблема "несколько точек регистрации без координации" решается через единый реестр учётных записей
- Без решения этих вопросов невозможно обеспечить базовую безопасность

#### II. Безопасность данных

**Почему включён:**

- Компания обрабатывает критические данные: ПДн клиентов и собственников, финансовые данные ЖКХ и сделок, токены доступа к гос.сервисам
- Требования законодательства РФ по защите ПДн - риск штрафов при несоответствии
- Отсутствие Data Governance блокирует создание новых ML/AI сервисов

#### III. Защита инфраструктуры

**Почему включён:**

- Необходима сегментация сети для изоляции партнёрских подсистем на техническом уровне
- Интеграции с госорганами и управляющими компаниями требуют защищённых каналов
- Техническая реализация изоляции данных на уровне инфраструктуры

#### IV. Управление инцидентами

**Почему включён:**

- Компенсирует проблему "один специалист по ИБ" через систематизацию процессов
- Критично для оперативного реагирования при обработке ПДн и финансовых данных
- Реакция на инцидент у конкурента (утечка данных в СМИ)

#### V.1. Общие вопросы

**Почему включён:**

- V.1.2 (VPN и шифрование для удалённого доступа) - критично для безопасного доступа к системам с ПДн
- V.1.4 (резервное копирование в облаке) - важно для восстановления данных, дополняет раздел II

Чек-лист сфокусирован на решении конкретных проблем PropDevelopment и подготовке к аудиту при ограниченных ресурсах (один специалист по ИБ). Исключены разделы, не связанные напрямую с критическими проблемами безопасности данных.
